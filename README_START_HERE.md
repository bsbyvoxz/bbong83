# codex test1 — 휠·이동·MP 판독 통합 수정

실행 파일명 `polar_v18.py`는 기존 런처 호환을 위해 유지했습니다. 수정된 전체 폴더를 새 Windows 디렉터리에 풀어 사용하세요. **실제 게임 입력·서버의 스킬 수락은 이 Linux 환경에서 검증하지 못했습니다.** 오프라인 테스트 통과는 완전한 자동사냥이나 충돌 없는 이동을 뜻하지 않습니다.

## 실행

1. 기존 Polar Python 프로그램을 F12로 종료하고 이전 AHK 스크립트도 트레이에서 종료합니다.
2. Windows에 Python **3.12 권장 (3.10–3.13 지원 범위)**, **AutoHotkey v1.1.37.02**를 설치합니다. AHK v2로 실행하지 마세요. AHK 설치 시 `.ahk` 연결을 설정하세요. 게임이 관리자 권한으로 실행 중이면 두 프로그램의 권한 수준도 맞아야 합니다.
3. `SETUP.bat` 실행: 설치된 64-bit Python 3.12/3.13/3.11/3.10과 PATH Python을 확인합니다. 없으면 Python Install Manager의 `py install 3.12`를 실행합니다. 그 다음 폴더 내부 `.venv` 생성, 버전 고정 의존성 설치, 단위·통합 테스트를 실행합니다. 손상된 `.venv`는 `.venv.previous-*`로 보존합니다. 오류가 있으면 실행을 중단합니다.
4. `START.bat` 실행 후 게임 창 활성화. AHK 준비 신호가 없으면 시작이 차단됩니다.
5. **캐릭터 발 바로 아래의 보이는 바닥**에 마우스를 놓고 **F9**. 몸/머리/스킬 이펙트 위에 등록하지 마세요. 등록한 지점이 이동 경로의 출발점입니다. 화면 좌표이며 절대 월드 좌표가 아닙니다.
6. **Ctrl+F9 네 번**: HP 바 왼쪽 → 오른쪽 → MP 바 왼쪽 → 오른쪽. 각 바의 동일한 가로 중앙선에 지점을 찍으세요. 게이지 값은 첫 F10 전에 등록해야 합니다.
7. **F10** 시작/일시정지. 기본 이동 ON. **F8** 이동 토글. **F11** 비상정지, **F12** 종료.
8. **Ctrl+F7** 최신 비동기 인식 결과 저장 (`vision_check.png`, `vision_scores.json`). **F7 단독은 게임 버프 키로 유지**하며 진단을 실행하지 않습니다.

최초 보정은 `gauge_points.json`에 클라이언트 크기와 함께 저장합니다. 창 크기가 바뀌면 Ctrl+F9 재보정과 F9 재등록이 필요합니다. 창 위치만 이동한 경우 보정 좌표는 유지되며, 안전을 위해 일시정지 후 F10으로 다시 시작합니다. 구버전의 창 크기 없는 좌표 파일은 자동 신뢰하지 않습니다. 창 포커스를 잃어도 자동으로 재개하지 않습니다.

## 수정한 동작

- 입력: 한 번에 하나의 복합 명령. `슬롯 1 → F3`와 `슬롯 2 → 해당 버프 → 슬롯 1`을 AHK **SendEvent**로 실행합니다. 우선순위·세션·만료시간·0.9초 실행 허가 갱신·전송 ACK를 적용합니다. 미확인 입력의 무조건 재전송을 하지 않습니다.
- F3: 정상 MP 확보 후 최우선. AHK `SENT` 시점 기준 10.25초 이상 간격. MP 변화가 550 소모와 양립하는지 별도 기록합니다. 이는 스킬 성공의 확정 증거가 아닙니다. 3회 연속 효과 미확인, ACK 누락, 포션 회복 미확인 시 멈춥니다.
- 버프: 최초 F1/F2/F6/F7 순서를 유지하고 F3·MP 보충 후 미완료 위치에서 재개합니다. 갱신은 신뢰할 수 있는 아이콘 소실 또는 285초 경과 기준입니다. 인식 실패는 `unknown`; pause/resume 때 전체 버프를 반복하지 않습니다. 중단 중 성공 여부가 모호한 버프는 최소 30초 보류합니다.
- 물약: HP **50% 이하**, MP **40% 미만**, 서로 다른 두 프레임 확인. 회복 확인 후 관찰을 다시 쌓습니다. MP 물약에 임의의 4초 쿨타임을 두지 않습니다. 2초 동안 회복이 관찰되지 않으면 추가 연타 대신 멈춥니다.
- 동전: 발밑 근거리 후보가 두 번 확인되고 카메라 추적이 신뢰될 때 **동전 추적 ID당 Z 1회**. 보이는 동안 기록이 만료되지 않으며 화면에서 사라져도 180초 보존합니다. 추적이 끊겨 동일성 판단이 불가능하면 기존 기록 만료까지 줍기를 보류합니다. 여러 더미가 겹치거나 오도메트리 오차가 큰 경우 완전한 동일성 보장은 불가능합니다. 동전으로 걸어가지 않습니다.
- 이동: 전체 화면의 거북이·여성 유령 밀집도를 비교하고 2마리 이상 큰 무리로만 목표를 바꾸는 유지 조건을 적용합니다. 클릭 경로 전체에 검은 영역·검출된 포탈/장애물 검사를 수행합니다. 클릭 한 번만 발행합니다.
- 끼임: 실제 전송 완료된 이동만 검사합니다. 공격·버프·물약·줍기에 의해 중단된 이동은 끼임으로 단정하지 않습니다. 배경 이동 불확실 시 이동 OFF. 탈출 클릭 전송만으로 성공 처리하지 않고 실제 이동을 재확인합니다. 반복 실패 시 이동 OFF, F8로 수동 재시도합니다.
- 종료/포커스 이탈 시 입력 허가 철회. 동일 게임에 두 제어기가 경쟁하지 않도록 Windows named mutex를 사용합니다. 로그 용량을 제한합니다.

## 로그 해석 및 실게임 확인

`status.txt`: `INPUT_ATTEMPT` → `BRIDGE_SENT` → `WHEEL_EFFECT`를 구분합니다.

- `mp_drop_consistent`: 관찰된 MP 하락이 F3 비용과 양립. 다른 게임 내 MP 효과까지 구분하는 확정 판정은 아닙니다.
- `unknown_mana_interference`: 물약/다른 마나 행동 때문에 판정 보류.
- `unconfirmed_no_retry`: 효과 미확인. 쿨다운을 초기화하거나 즉시 F3 재전송하지 않습니다.
- `bridge_status.txt`: AHK가 실제 SendEvent를 수행한 명령 ID와 상태. 게임 서버 수락 확인이 아닙니다.

첫 실행은 사람이 보면서 **숫자 1 → F3 실제 시전**, **버프 4개와 슬롯 복귀**, **게이지 수치**, **F11 정지**부터 확인하세요. 문제가 있으면 `status.txt`, `bridge_status.txt`, 해당 구간 MP 바가 보이는 짧은 영상이 진단에 도움이 됩니다. 비밀번호/계정 정보는 필요 없습니다.

## 오프라인 재검증

Windows: `.venv\Scripts\python.exe TEST_OFFLINE.py`

Linux: `python -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt`, `.venv/bin/python TEST_OFFLINE.py`

가벼운 수정본 ZIP에는 원본 MP4를 중복 포함하지 않습니다. 영상 조각 두 개를 `references/`에 넣고 `REASSEMBLE_VIDEO.py`를 실행하거나, 복원한 영상 경로를 지정하세요:

```
python TEST_OFFLINE.py --video "경로/gameplay_camera_motion.mp4" --require-video
```

영상 SHA-256을 검사하고 전체 프레임 디코딩, 약 4fps 배경 추적, 1fps 탐지·경로 검증을 수행합니다. `regression_output/results.json`과 주석 이미지를 생성합니다. 영상이 없으면 영상 검사를 **skipped**로 명시하며 `--require-video`로 누락을 실패 처리할 수 있습니다.

## 남아 있는 한계

탐지기는 학습된 범용 모델이 아닌 템플릿 기반입니다. 겹침·회전·조명·축척 변화로 몬스터를 놓쳐 밀집도를 과소평가할 수 있습니다. 검출되지 않은 계단·포탈·기둥까지 회피한다고 보장할 수 없습니다. 녹화물의 캐릭터 위치도 고정 중심이 아니므로 영상 경로 평가는 **가상의 앵커에 대한 기하 검사**입니다. 실제 목적지 도달이나 사냥 효율을 증명하지 않습니다. 미니맵/절대 좌표가 없어 출발점 복귀를 보장하지 않습니다.

주변 플레이어/아이템 소유권 판별, 자동화 은폐 및 탐지 회피는 구현하지 않았습니다. 게임 운영 규정을 확인하세요. 자동화는 계정 제재 대상일 수 있으며 무인 실행을 권장하지 않습니다.
